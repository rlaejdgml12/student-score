## 🧩 코테 07 — 해시맵·해시셋

- **선형 탐색 O(N×M) vs 해시 탐색 O(N+M)**: 두 리스트를 서로 다 비교하면 곱셈이지만, 한쪽을 해시에 담아두면 조회가 O(1)이라 덧셈 스케일로 줄어든다.
- **배열·해시·정렬 중 선택 기준**: 인덱스가 연속된 숫자(예: 알파벳)면 배열(`c - 'a'`로 바로 인덱스 계산), 키가 임의의 값이면 해시, 순서·범위 비교가 필요하면 정렬.
- ⭐ **HashMap은 순서를 보장하지 않는다** — 넣은 순서를 지키고 싶으면 `LinkedHashMap`, 정렬된 순서가 필요하면 `TreeMap`.
- ⭐ **"존재하는가?" → Set / "몇 개인가?" → Map**: 단순 존재 여부만 필요하면 `Set`으로 충분하고, 개수(빈도)까지 세야 하면 `Map`이 필요하다. (동명이인이 여러 명 있는 경우처럼, Set만 쓰면 몇 명인지는 알 수 없다는 함정)
- ⭐ **해시는 key → value 한 방향만 빠르다**: `get(key)`는 O(1)이지만, 거꾸로 "이 value를 가진 key가 뭐야?"는 전체를 순회해야 하는 O(N)이다.
- **복합 key를 만드는 3가지 방법**: ① `record`로 두 값을 묶어 하나의 key 객체로 ② 구분자를 넣은 문자열(`x + "," + y`)로 합치기 ③ 2차원 배열/좌표 자체를 key로. 구분자 없이 그냥 이어붙이면(`"" + x + y`) 서로 다른 (x, y)가 같은 문자열이 되는 충돌이 생길 수 있다.
