# 2026-08-06 (목) — 3주차: 자바 기본 01~05

## 01 클래스와 데이터
- 클래스/객체/인스턴스 차이: 클래스는 설계도, 객체는 그 설계도로 만든 실체. 인스턴스는 그 객체가 "어느 클래스에서 나왔는지"를 강조할 때 부르는 이름 — 객체와 인스턴스는 같은 대상을 다르게 부르는 것.
- 객체 배열의 함정: `new Student[2]`는 객체 2개가 아니라 참조값을 담을 빈 칸 2개. 각 칸에 직접 `new Student()`를 넣지 않으면 `null` 상태라 필드 접근 시 NullPointerException.

## 02 기본형과 참조형
- 대원칙: 자바의 모든 대입은 항상 값 복사. 기본형은 실제 값을 복사, 참조형은 참조값(주소)을 복사.
- changeValue vs replace 차이: 매개변수는 항상 참조값을 받는 건 동일. `changeValue`는 그 참조값을 따라가 **객체 내부 필드를 변경**해서 호출한 쪽에도 반영됨. `replace`는 매개변수 **자체를 다른 객체로 재대입**해서 호출한 쪽 변수에는 영향 없음. → 이 차이가 자바가 call by value인 이유.

## 03 객체 지향 프로그래밍
- 절차 지향 vs 객체 지향 초점 차이: 절차 지향은 "어떻게 처리할 것인가"에 초점을 두고 기능을 main(또는 외부)에 흩어둠. 객체 지향은 "무엇이 어떤 책임을 가질 것인가"에 초점을 두고, 데이터를 가장 잘 아는 객체 안에 관련 기능을 직접 둠.
- 응집도란: 데이터와 그 데이터를 다루는 기능이 한 곳(클래스)에 얼마나 잘 모여 있는지의 정도. 단, 여러 객체를 조정하는 로직·외부 시스템 호출 등 한 객체의 책임을 넘는 일은 Service 같은 별도 역할이 맡는 게 자연스러움.

## 04 생성자
- 생성자가 왜 필요한가: 객체를 만든 직후 값을 따로 채우면 그 사이 유효하지 않은 상태가 될 수 있음. 생성자로 처음부터 필요한 값이 채워진 상태로 객체를 만들 수 있음.
- this vs this() 차이: `this`는 지금 만들어지는 객체 자신(필드 접근용), `this(...)`는 같은 클래스의 다른 생성자를 호출하는 것(생성자 위임). 완전히 다른 역할.
- 기본 생성자가 자동 생성되는 조건: 클래스에 생성자를 **하나도** 직접 선언하지 않았을 때만. 하나라도 직접 만들면 자동 제공 중단.
- (추가) 메서드/생성자 오버로딩: 이름은 같고 매개변수 개수·타입이 다른 것. 반환 타입만 다른 건 오버로딩 아님.

## 05 패키지
- 패키지가 필요한 이유: 클래스가 많아지면 이름이 충돌할 수 있어서, 타입 이름을 구분하는 네임스페이스로 관련 클래스를 묶어 관리.
- 이름 없는 패키지를 지양하는 이유: 이름 없는 패키지(default)의 클래스는 이름 있는 다른 패키지에서 import할 수 없어서, 여러 패키지로 구성되는 실제 프로젝트에서는 못 씀.
- (추가) 패키지 폴더 이름은 자바 식별자 규칙을 따라야 함 — 숫자로 시작 불가, 하이픈 사용 불가 (오늘 트러블슈팅 참고).

## 트러블슈팅 기록
- **중복 클래스 이름 에러**: 한 파일에 `Book` 클래스를 두 개(필드용 + main용) 만들어서 `duplicate class` 에러. → main을 담은 클래스 이름을 `Main`으로 분리해서 해결.
- **public class와 파일명 불일치**: `public class Book`인데 파일명이 `Book.java`가 아니어서 `class Book is public, should be declared in a file named Book.java` 에러. → 자바 규칙: public 클래스는 파일명과 반드시 일치해야 하고, 한 파일에 public 클래스는 하나만 가능. 데이터 클래스는 `public` 떼고, main 담은 클래스만 파일명과 맞춰 `public` 유지.
- **패키지 폴더 이름 규칙 위반**: `practice/2026-08-06/`(하이픈, 숫자로 시작) 폴더를 만들었더니 IntelliJ `New` 메뉴에 `Java Class`가 아예 안 뜸. → 원인: 자바 패키지 이름은 자바 식별자 규칙을 따라야 해서 숫자 시작·하이픈 불가. `_2026_08_06`(밑줄 시작)으로 변경해서 해결.
- **컴파일 출력 경로 미설정**: "The output path is not specified for module student-score" 에러. → Project Structure → Project → Project compiler output 경로 지정(`.../student-score/out`)으로 해결.
