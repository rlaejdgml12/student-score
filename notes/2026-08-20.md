## 07 HashSet과 equals/hashCode

- **HashSet이 중복을 판단하는 2단계** ✅ — `hashCode()`로 갈 버킷을 정하고, 그 버킷 안의 기존 값들과 `equals()`로 비교해 최종 판정. 그래서 **둘을 세트로 재정의**해야 한다.
- **동일성 vs 동등성** — 동일성(identity)은 `==`, 즉 **같은 객체(주소)인가**. 동등성(equality)은 `equals()`, 즉 **논리적으로 같은 값인가**. `equals`를 재정의한다는 건 "이 클래스에서 '같다'의 기준을 내가 정하겠다"는 선언.
- **하나만 재정의하면 생기는 일** ✅ — `hashCode`만 하면 같은 버킷에 가지만 `equals`가 주소 비교라 중복으로 안 봄. `equals`만 하면 **다른 버킷으로 흩어져서 비교조차 안 일어남**. 둘 다 중복 제거 실패.
- **동등성 계약 5가지** — 반사성(`x.equals(x)`는 true) / **대칭성**(`x.equals(y)`면 `y.equals(x)`도 true) / 추이성 / 일관성(필드가 안 바뀌면 결과도 안 바뀜) / `x.equals(null)`은 항상 false.
  - 추가로 **`equals`가 true면 `hashCode`도 반드시 같아야 한다.** 반대는 아님(해시 충돌은 허용).
  - `hashCode()`가 `return 42`처럼 상수여도 **계약 위반은 아님** — 다 한 버킷에 몰려서 O(n)이 될 뿐 기능은 정상.
- **상속에서 instanceof 기반 equals가 위험한 이유** ✅(방향 맞음) — 자식은 부모 타입이기도 해서 `cp instanceof Point`는 true인데, `p instanceof ColorPoint`는 false. **화살표가 한쪽으로만 통해서 대칭성이 깨짐.** 그러면 컬렉션에서 넣은 순서에 따라 `contains` 결과가 뒤집힌다.
  - 해법: 값 객체는 `final` 클래스나 `record`로 만들거나, `getClass()` 비교를 쓴다. **StudentScore의 `Student.equals`가 이미 `getClass()` 방식이라 안전함.**
- **record가 자동으로 만들어주는 것** — 필드(자동 final), 생성자, **`equals`·`hashCode`·`toString`**, getter(이름에 `get` 안 붙음). 상속이 아예 불가(자동 final)라 위의 대칭성 문제가 발생 불가능.
  - ⚠️ JPA 엔티티는 record로 만들면 안 됨(식별자가 나중에 채워지고 값도 변함).
- **저장한 뒤 필드를 바꾸면** ✅ — HashSet은 `add` 시점의 hashCode로 버킷을 정하고 **다시 계산하지 않는다.** 필드를 바꾸면 객체는 원래 버킷에 있는데 새 해시는 다른 버킷을 가리켜서 **`contains`도 `remove`도 실패**. `size()`는 1인데 꺼낼 수도 지울 수도 없는 유령이 남는다.
  - → **equals/hashCode에 쓰는 필드는 `final`로 박아라.**

## 08 Set 구현체

- **세 구현체 차이** ✅(부분) — `HashSet` 순서 없음(가장 빠름, 기본 선택) / `LinkedHashSet` 넣은 순서 유지 / `TreeSet` **정렬된 순서** 유지.
  - 성능: HashSet은 평균 **O(1)**, TreeSet은 내부가 트리라 **O(log n)**. 정렬이 꼭 필요한 게 아니면 HashSet.
- **⭐ TreeSet의 중복 판단 기준** — `equals`가 **아니라** `compareTo()`/`Comparator`의 **비교 결과가 0인지**로 판단한다.
  - `HashSet` → `hashCode()` + `equals()`
  - `TreeSet` → **compare 결과 0**
  - 그래서 점수만 기준으로 잡으면 `kim(90)`과 `lee(90)`이 같은 원소로 취급돼 **lee가 조용히 사라진다.**
  - TreeMap은 더 나쁨 — 버리는 게 아니라 **기존 값을 덮어쓴다.**
- **동점자가 사라지는 걸 막는 방법** ✅ — `.thenComparing(...)`으로 2순위 기준을 붙여 **비교 결과가 0을 벗어나게** 만든다.
  - ⭐ `Comparator`는 정렬 기준이면서 **동시에 중복 판단 기준**이다.
- **higher / ceiling 차이** — 자기 자신을 포함하느냐만 다르다.
  - `higher(x)`/`lower(x)` = **초과 / 미만** (x 자신 제외)
  - `ceiling(x)`/`floor(x)` = **이상 / 이하** (x가 있으면 x 자신을 반환)
  - 해당하는 값이 없으면 **`null` 반환** → 쓰기 전에 null 체크 필요.
- **headSet이 돌려주는 것** — 새 집합이 아니라 **원본을 들여다보는 뷰(view)**. 뷰에서 지우면 **원본에서도 사라진다.**
  - 안전하게 쓰려면 `new TreeSet<>(scores.headSet(90, true))`처럼 감싼다 = **방어적 복사**.

## 09 Map·Stack·Queue

- **같은 키로 또 put하면** — **값을 덮어쓴다.** (Set의 `add`는 중복이면 그냥 무시하고 `false` 반환. 여기가 다름)
  - 순서는 안 바뀜 — `LinkedHashMap`에서 두 번째 자리였으면 그 자리를 지킨다.
  - `put`은 **밀려난 이전 값을 반환**한다.
- **세 구현체** — Set과 1:1 대응. `HashMap`(순서 없음, 기본) / `LinkedHashMap`(넣은 순서) / `TreeMap`(**key 기준** 정렬).
  - 참고: 파이썬 `dict`는 삽입 순서를 유지하므로 자바에서 가장 비슷한 건 `LinkedHashMap`.
- **HashMap의 null 규칙** — **null key를 하나** 허용, null value는 여러 개 허용.
  - ⚠️ `get()`이 null을 반환할 때 "키가 없음"인지 "값이 null"인지 구분이 안 됨 → **`containsKey()`로 구분**.
  - `ConcurrentHashMap`은 이 모호함 때문에 null을 **아예 금지**한다.
- **merge — 세 인자** — `count.merge(키, 없을때_넣을_값, 있을때_합치는_방법)`
  - 키가 없으면 두 번째 인자를 그냥 넣고, **합치는 함수는 실행조차 안 함.**
  - 있으면 세 번째 함수로 기존값과 새값을 합침.
  - 단어 세기 표준: `count.merge(word, 1, Integer::sum)` — `if/else` 4줄이 한 줄로.
- **computeIfAbsent — 키가 이미 있으면** — **함수를 실행하지 않고** 기존 값을 그대로 반환한다.
  - 없을 때만 함수를 실행해 값을 만들고, 맵에 넣고, 그 값을 반환.
  - **어느 쪽이든 값을 반환**하기 때문에 `.add(...)`를 바로 이어 붙일 수 있다.
  - `group.computeIfAbsent("backend", k -> new ArrayList<>()).add("spring");` — 5줄이 한 줄로.
  - ⚠️ 인자 둘은 **쉼표**로 구분하고, `.add()`는 **괄호 밖**에 붙인다.
- **Deque 하나로 스택과 큐** — `ArrayDeque` 하나로 둘 다 된다. 쓰는 메서드가 성격을 정함.
  - `push`/`pop` → **스택(LIFO)**, `offer`/`poll` → **큐(FIFO)**, `peek`은 양쪽 다 "꺼내지 않고 보기만".
- **Stack 클래스 대신 Deque를 쓰는 이유** — ①모든 메서드에 동기화가 걸려 있어 혼자 쓸 때도 느림 ②상속 구조가 잘못돼서 **중간 원소를 꺼낼 수 있어 스택 규칙이 깨짐**.
  - 표준: `Deque<String> stack = new ArrayDeque<>();`
  - ⚠️ 실패했을 때 반응이 다른 두 계열: `remove()`/`element()`는 **예외**, `poll()`/`peek()`은 **null**. 실무는 후자를 많이 씀.
- **PriorityQueue를 그냥 출력하면** — 내부가 **힙(트리)**이라 완전 정렬이 아니다. **"부모가 자식보다 작다"만 지킬 뿐**, 형제끼리는 순서가 없다.
  - 그래서 `[10, 50, 30]` 같은 게 나온다 — 맨 앞이 최솟값인 것만 보장.
  - 정렬된 순서로 보려면 **`poll()`을 반복**해야 한다.
  - 최대 힙은 별도 클래스가 없고 `new PriorityQueue<>(Comparator.reverseOrder())`로 만든다.
  - 힙을 쓰는 이유: 정렬된 배열은 넣기 O(n), 정렬 안 된 배열은 빼기 O(n)인데 **힙은 양쪽 다 O(log n)**.

## 10 순회·정렬

- **Iterable과 Iterator** — `Iterable`은 "나는 순회 가능하다"는 **명찰**(`iterator()` 제공), `Iterator`는 실제로 도는 **커서**(`hasNext`/`next`/`remove`).
  - 자료구조 강의의 `Node p = head; ... p = p.link;`가 정확히 `Iterator`가 하는 일.
  - **핵심 가치**: 도는 방법(배열은 index++, 연결리스트는 node.next, 트리는 중위순회)을 **감춰서**, 어떤 컬렉션이든 `hasNext`/`next` 두 개로 순회할 수 있게 한다.
- **향상된 for문이 실제로 하는 일** — 컴파일러가 `Iterator`를 발급받아 `while (it.hasNext()) { it.next(); }` 형태로 바꾼다.
  - ⚠️ **배열은 `Iterable`이 아닌데도** 향상된 for문이 된다(컴파일러가 인덱스 for문으로 바꿈). 정확한 문장은 **"Iterable이거나 배열이면 쓸 수 있다."**
  - `Map`은 `Iterable`이 아니라 바로 못 돈다 → `keySet()`이나 `entrySet()`으로 꺼내야 함.
- **ConcurrentModificationException** — 순회 중에 **구조가 바뀌면**(add/remove) 커서가 위치를 잃어서 터진다. `ArrayList`가 구조 변경 횟수를 세고 있다가 커서가 아는 값과 다르면 즉시 던짐.
  - **fail-fast** — 원소를 건너뛰는 조용한 버그로 남기느니 요란하게 터뜨리자는 설계.
  - ⚠️ 이름이 `Concurrent`지만 **멀티스레드와 무관**. 스레드 하나짜리 코드에서도 난다.
  - **읽기만 하거나 `set()`으로 값만 바꾸는 건 안전** — 크기가 안 변하니까.
- **순회 중 안전하게 삭제하는 두 가지**
  - `it.remove()` — 커서가 직접 지우니 카운터도 같이 맞는다. (⚠️ 반드시 `next()` 이후에 호출)
  - `list.removeIf(조건)` — 한 줄이고 실수 여지가 없다. **실무 표준.**
- **Comparable과 Comparator**
  - `Comparable`의 `compareTo(other)` — 인자 1개, **this와 비교**. 클래스가 **타고난 기본 정렬 기준**, 하나만 가능.
  - `Comparator`의 `compare(a, b)` — 인자 2개, **바깥에서 둘을 놓고 판정하는 심판**. 여러 개 만들어 상황마다 골라 씀.
  - 실무 감각: `Comparable`은 순서가 진짜 하나로 딱 정해질 때(돈·날짜·버전)만. 애매하면 `Comparator`.
- **reversed를 어디 붙이느냐** — `.reversed()`는 **그 앞까지 만들어진 기준 전체**를 뒤집는다.
  - `comparingInt(getScore).reversed().thenComparing(getName)` → 점수↓, 동점이면 이름↑ **(보통 원하는 것)**
  - `comparingInt(getScore).thenComparing(getName).reversed()` → 전체가 뒤집혀 **이름도 ↓**
- **compareTo에서 뺄셈을 쓰면 안 되는 이유** — `this.score - other.score`는 **정수 오버플로우** 위험. `int` 최댓값이 약 21억인데 `20억 - (-20억)`은 40억이라 **음수로 뒤집혀** 정렬이 조용히 깨진다.
  - → `Integer.compare(a, b)` (long은 `Long.compare`, double은 `Double.compare`)
- **Arrays.asList에 add가 안 되는 이유** — **배열은 크기가 고정**인데, `Arrays.asList`는 새 리스트를 만드는 게 아니라 **배열에 List 껍데기만 씌운 것**이다.
  - `set()`은 칸 값만 바꾸니 OK, `add()`는 칸을 늘려야 하니 `UnsupportedOperationException`.
  - `ArrayList`가 `add`를 지원하는 건 `MyArrayList`에서 직접 만든 **배열 증설(grow)** 기능이 있어서.
  - 안전하게: `new ArrayList<>(Arrays.asList(...))`로 감싸면 진짜 리스트가 된다.
- **Collections vs Arrays** — `Collections`는 컬렉션용, `Arrays`는 배열용 유틸.
  - ⚠️ `Collection`(인터페이스)과 `Collections`(유틸 클래스)는 **글자 하나 차이인데 완전히 다르다.**
  - 배열은 그냥 출력하면 주소가 나오므로 `Arrays.toString(arr)`로 감싼다.

## 오늘 만든 것 — StudentScore v10

- **`StudentRanking.rankByAverage(List<Student>)`** — 학생 리스트를 받아 **평균 내림차순, 동점이면 이름 오름차순**으로 정렬한 **새 리스트**를 반환. 원본을 건드리지 않으려고 `new ArrayList<>(students)`로 복사부터 함(방어적 복사).
  ```java
  result.sort(Comparator.comparingDouble(Student::averageScore).reversed()
                        .thenComparing(Student::getName));
  ```
- **`StudentRanking.groupByGrade(List<Student>)`** — 학생을 **등급별로 묶어** `Map<Grade, List<Student>>`로 반환. 09에서 배운 `computeIfAbsent`를 그대로 씀.
  ```java
  ranked.computeIfAbsent(s.getGrade(), k -> new ArrayList<>()).add(s);
  ```
  - 그룹 안의 순서는 원본 순서 그대로 → 정렬해서 넣고 싶으면 `groupByGrade(rankByAverage(students))`.
- **`Student.toString()` 추가한 이유** — 없으면 리스트를 출력할 때 `studentscore...Student@1b6d3586` 같은 **주소**가 나온다. `String.format("%.1f", ...)`로 평균 소수점을 한 자리로 잘랐다(안 그러면 `91.66666666666667`).

## 트러블슈팅

- **한 파일에 `public class` 두 개** — 자바는 한 파일에 `public class` 하나만 허용. `main`을 별도 클래스로 빼면서 발생. 게다가 `static` 중첩 클래스는 바깥 클래스 안에 있어서 다른 클래스에서 이름만으로는 못 찾는다. 클래스명은 **파일명과 글자 하나까지 일치**해야 한다.
- **생성자 매개변수 이름 오타 — 오늘 두 번** (`GoodMember(String emain)`, `Student(String name, int Score)`) — 매개변수와 대입하는 이름이 어긋나면 우변이 **필드 자기 자신**을 가리켜서, 아직 초기화 안 된 final 필드를 읽으려다 컴파일 에러.
  - → **생성자는 손으로 쓰지 말고 `Alt + Insert` → Constructor로 생성할 것.**
- **`Set.add`에 인자를 두 개** (`broken.add("kim", 90)`) — `Set`은 **원소 하나**를 담는 그릇이라 `add`는 인자가 하나. `Student` 객체를 먼저 만들어서 넣어야 한다. 인자 두 개를 받는 건 **Map의 `put(키, 값)`**.
- **computeIfAbsent 괄호 위치** — 인자 둘은 **쉼표**로 구분하고(`->` 아님), `.add()`는 **괄호 밖**에 붙인다.
  ```java
  ranked.computeIfAbsent(s.getGrade(), k -> new ArrayList<>()).add(s);
  //                     ───┬────  ─────────┬──────────      └─ 괄호 밖
  //                      첫 인자        둘째 인자(람다)
  ```
  - 람다 변수명을 바깥 for문의 `s`와 같게 쓰면 `variable s is already defined` 에러 → `k`로.

## 내일 복습할 것

- ⭐ **`instanceof`와 선언 타입 vs 실제 객체** — 8/7에 배웠는데 오늘 다시 통째로 헷갈렸다. `Object o = Integer.valueOf(100)`에서 `o instanceof Integer`가 **true**인 이유(라벨이 아니라 내용물을 본다), `o instanceof Object`도 **true**인 이유(모든 클래스의 조상). 업캐스팅은 자동, 다운캐스팅은 수동이고 위험하다는 것까지.
- **동등성 계약 5가지**를 이름만 보고 말할 수 있게 (반사·대칭·추이·일관·null).
