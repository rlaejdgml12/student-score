# 2026-10-21 (수) 능동회상 노트

## 코테 05 완전탐색·브루트포스

### §2 완전탐색 기본
- 완전탐색(브루트포스)은 정답이 될 수 있는 후보를 빠짐없이 전부 만들고, 각 후보가 조건을 만족하는지 검사해서 답을 고르는 방식입니다. 정답이 보장되고 조건을 코드로 옮기기 쉽지만, 후보 수가 많아지면 시간 초과가 나므로 입력이 작을 때 씁니다.

### §3 설계 순서
- 설계 순서는 ① 후보 정의 → ② 후보 개수 계산 → ③ 중복 없는 생성 → ④ 조건 검사 → ⑤ 답 갱신(최댓값·최솟값·첫 정답·N번째)입니다. 얼마나 걸리는지(후보 수)를 먼저 따져 보는 것이 맞는 방향이고, 입력 크기로 통과 가능한지 가늠한 뒤에 코드를 짭니다.
- 복잡도 감각: 부분집합은 원소마다 넣음/안 넣음 두 가지라 2^n, 순열은 순서가 다르면 다른 경우라 n!입니다. (i < j < k는 부분집합이 아니라 "세 원소를 중복 없이 고르는 조합"을 만드는 구조입니다.)

### §4 단일 반복문 탐색
- 후보 범위 순회: 정답 후보가 연속된 정수 범위에 있고 후보 하나의 검사 비용이 크지 않을 때, 반복문 하나로 작은 값부터 검사합니다. 가장 작은 정답은 첫 정답에서 break로 끝내야 합니다(안 끝내면 뒤의 더 큰 생성자가 answer를 덮어씁니다). break는 가장 안쪽 반복문 하나만 끝냅니다.
- 영화감독 숌: number는 지금 검사 중인 수(666이 들어 있는지 볼 대상), count는 지금까지 찾은 "666 포함 수"의 개수입니다. count가 N이 되는 순간 그때의 number가 답입니다.

### §5 모든 쌍 비교
- i < j는 두 원소를 순서 없이 한 쌍씩만 고르는 조합(A,B와 B,A를 같은 것으로 취급)이고, 모든 순서쌍은 (A,B)와 (B,A)를 따로 보는 것입니다(i != j인 이중 반복). 덩치처럼 "누가 누구보다 큰가" 방향이 있는 비교는 모든 순서쌍을 봅니다.
- 덩치의 rank는 "자기보다 키와 몸무게가 모두 큰 사람 수 + 1"입니다(1로 시작해서 더 큰 사람을 만날 때마다 1씩 증가).

### §6 세 수 선택
- 같은 원소를 두 번 고르지 않고, 순서만 다른 같은 조합(1,2,3과 2,1,3)을 한 번만 세려고 i < j < k 구조를 씁니다.
- break는 가장 안쪽 반복문 하나만 끝냅니다. 전체를 끝내려면 메서드 return, 라벨, 플래그를 씁니다.

### §7 숫자와 자릿수 완전탐색
- 각 자리 합은 자릿수를 더한 값이고(666이면 6+6+6=18), 분해합은 "자기 자신 + 각 자리 합"입니다(666 → 666+18=684). 분해합이 N이 되는 수를 N의 생성자라고 하며(684의 생성자는 666), 생성자가 여러 개면 가장 작은 것을 답으로 합니다.
- 666 포함 검사: 숫자는 int로 증가시키며 세고, 포함 여부는 String.valueOf(number).contains("666")처럼 문자열로 바꿔 검사합니다.

### §8 2차원 격자 완전탐색
- N×M 격자에서 K×K 부분 격자의 시작점 개수는 (N-K+1)(M-K+1)입니다. 체스판은 8×8이라 (N-7)(M-7)이고, 시작점 반복문은 `<= n-k`까지 돌아야 마지막 시작점이 빠지지 않습니다.
- 체스판 기대 색: 칸의 (행+열)이 짝수인지 홀수인지로 그 자리에 와야 할 색(W/B)을 정합니다. 시작 색이 W인 패턴과 B인 패턴은 서로 정반대입니다.
- Math.min(count, 64 - count): count는 한 패턴으로 만들 때 다시 칠할 칸 수이고, 반대 패턴은 정확히 64-count이므로 둘 중 작은 쪽이 답입니다.

### §9 순열·조합·부분집합 맛보기
- 순열 재귀: 아직 안 쓴 원소를 고르고(used[i]=true) → 다음 자리로 재귀 → 돌아오면 used[i]=false로 되돌려서 다음 후보를 시도합니다.
- 조합 재귀: combination(depth, start)에서 다음 자리는 value+1부터 고릅니다. 앞에 쓴 값 이하로는 돌아가지 않으므로 순서만 다른 같은 조합이 생기지 않습니다.
- 부분집합 재귀: 원소마다 "안 넣음" 가지로 재귀하고, 돌아와서 "넣음" 가지로 재귀합니다. 끝 원소까지 결정되면 부분집합 하나가 완성됩니다.
- 비트마스크: mask를 이진수로 읽어 i번째 비트가 1이면 i번 원소를 선택한 것입니다(arr=[3,7,2], mask=5=101 → 3과 2). mask를 0부터 2^n-1까지 돌리면 모든 부분집합을 순회합니다.

### §10 가지치기와 백트래킹 연결
- 가지치기가 안전한 조건: 이후 어떤 선택을 해도 조건을 다시 만족할 수 없다고 보장될 때입니다. 예를 들어 값이 전부 양수라 합이 늘기만 하면 `sum > target`에서 잘라도 됩니다.
- 백트래킹은 완전탐색과 별개의 알고리즘이 아니라, 탐색 중 정답이 될 수 없는 분기를 미리 중단하는 가지치기 방식입니다. 최악의 경우엔 가지치기가 거의 안 되어 전체를 다 볼 수도 있습니다.
- N-Queen: 한 행에 퀸이 둘이면 서로 공격하므로 n개를 놓으려면 행마다 정확히 하나씩 놓아야 합니다. 그래서 행 단위로 재귀하면 행 충돌은 처음부터 없고, 열(col[])과 두 대각선(row+col, row-col이 같으면 같은 대각선)만 검사합니다.
- 경우의 수 감각: 순열 n!/(n-m)!, 조합 nCm, 부분집합 2^n이며, 전체 비용은 "경우의 수 × 경우 하나를 검사하는 비용"입니다. 1초 ≈ 1억 연산이라 순열은 n≈10, 부분집합은 n≈20 정도까지가 한계입니다.

### §11 대표 문제 분석
- 블랙잭 = 서로 다른 세 수 조합(i<j<k), 분해합 = 단일 후보 순차 탐색, 덩치 = 모든 쌍 비교, 체스판 = 모든 부분 격자 시작점(완전탐색+시뮬레이션), 영화감독 숌 = 조건을 만족하는 N번째 수 찾기. 전부 완전탐색입니다.
- 1182: 목표 합이 0일 때 아무것도 고르지 않은 빈 부분집합(합 0)이 정답으로 세어지지 않도록 selectedCount > 0을 확인합니다.
- 14889: N/2명을 조합으로 뽑아 한 팀(스타트)으로 두고 나머지가 링크팀이 됩니다. 각 팀 안의 모든 쌍 (i,j)에 대해 S[i][j]+S[j][i]를 더해 팀 점수를 구하고, 두 팀 점수 차이의 최솟값을 찾습니다.
- 14888: 연산자를 쓰기 전에 operators[op]--, 재귀에서 돌아오면 operators[op]++로 복구합니다. 복구하지 않으면 첫 경로에서 연산자가 소진되어 다른 연산자 순서를 시도할 수 없습니다.

### §12 자주 하는 실수
- 입력 크기를 보지 않고 중첩 반복문을 쓴다 / 같은 원소를 두 번 고르거나 순서만 다른 조합을 반복한다(i<j, i<j<k) / break가 모든 반복문을 끝낸다고 착각한다(가장 안쪽만 종료) / 시작점 범위를 `< n-k`로 써서 마지막 시작점을 빠뜨린다(`<= n-k`) / 체스판에서 한 패턴만 검사한다(`64-count` 필요) / 덩치에서 &&가 아니라 ||를 쓴다 / 안전하지 않은 가지치기로 정답을 잘라낸다 / Math.pow(2,n)을 쓴다(1<<n, 크면 1L<<n) / 합이 int 범위를 넘는데 long을 안 쓴다.

### §13 실전 적용 판단 순서
- ① 후보 정의 → ② 후보 개수 계산(N², N³, 2^N, N!) → ③ 입력 크기로 통과 가능 여부 확인 → ④ 중복 없는 생성 구조(i<j, i<j<k) 결정 → ⑤ 조건 검사 코드화와 답 갱신 방식 결정(최댓값·최솟값·N번째·조기 종료) → ⑥ 2차원이면 시작점 범위와 시뮬레이션 분리 → ⑦ 안전한 최적화·가지치기 검토.

### §14 개념 확인 7문항
1. 모든 두 원소를 중복 없이 선택하는 반복문
- `for (int i = 0; i < n; i++) { for (int j = i + 1; j < n; j++) { ... } }` — j를 i+1부터 시작해서 같은 원소 중복과 (i,j)/(j,i) 중복을 모두 막습니다. (완전탐색은 방식의 이름이고, 반복문 구조는 이 모양입니다.)
2. 세 원소 삼중 반복문에서 i < j < k 구조가 필요한 이유
- 같은 원소를 두 번 고르는 것과, 순서만 다른 같은 조합(1,2,3과 2,1,3)을 여러 번 세는 것을 막기 위해서입니다.
3. N×M 격자에서 K×K 부분 격자의 시작점 개수 식
- (N-K+1) × (M-K+1)입니다. (N-K가 아니라 +1이 붙습니다. 마지막 시작점이 인덱스 N-K이므로 0부터 세면 N-K+1개입니다.)
4. 완전탐색과 시뮬레이션의 차이
- 완전탐색은 가능한 후보를 전부 만들어 검사하는 방식이고, 시뮬레이션은 문제에 주어진 규칙을 순서대로 실행하는 방식입니다. 체스판처럼 모든 시작점 후보(완전탐색)에 대해 각 시작점에서 규칙대로 결과를 계산(시뮬레이션)하는 식으로 함께 쓰입니다.
5. 재귀 부분집합 탐색과 비트마스크 부분집합 탐색 비교
- 재귀는 원소마다 "안 넣음/넣음" 두 갈래로 내려가므로 중간에 가지치기를 넣기 쉽습니다. 비트마스크는 0부터 2^N-1까지 정수의 비트로 선택을 표현하는 반복문 하나라 코드가 짧지만 중간에 자르기 어렵고, 비트 폭 때문에 보통 N ≤ 20 정도에서 씁니다.
6. Math.pow(2, n)을 반복문의 경계값으로 쓰지 않는 이유
- Math.pow는 double을 반환해서 정수 반복의 경계로 쓰려면 형 변환이 필요하고, 비트마스크 의도도 드러나지 않습니다. n이 작으면 `1 << n`, 크면 `1L << n`을 씁니다.
7. 음수가 포함된 합 문제에서 currentSum > target 가지치기가 위험한 이유
- 현재 합이 target을 넘었더라도 뒤에서 음수를 더하면 다시 줄어들 수 있어서, 정답이 될 수 있는 후보까지 잘라내기 때문입니다.
